# MAR-003 — Importer une recette Marmiton : neutre, copie, lien d'origine (back)

- **Dépôt** : **back** ; le front est MAR-004
- **Taille** : L
- **Effort recommandé pour l'agent** : **xhigh** (migration, propriétaire sans compte, droits qui ne doivent jamais s'ouvrir, appel sortant)
- **Dépend de** : MAR-001 (lecteur de page) et MAR-002 (lecture des lignes), **fusionnés dans `main`**
- **Statut** : à faire
- **Lire d'abord** : [ADR 0037](../../adr/0037-copier-une-recette-depuis-marmiton.md) en entier ; `CLAUDE.md` (puces « Recette secrète », « Ingrédients propres à chaque utilisateur », « Bornes et plafonds de `Repas` », « Contextes étanches ») ; `CopyRecipeHandler` ; `docs/ingredients/rapprochement.md` ; skill `repas-dev` ; issue #434.

## But

`POST /api/v1/recipes/import/marmiton` `{url}` : l'utilisateur reçoit sa copie d'une recette Marmiton ; la recette neutre est créée une fois pour tous ; le lien d'origine est rendu par la fiche. Tout se décide dans l'ADR 0037 : ce ticket l'applique, il ne le rediscute pas (écart ou impossibilité : l'écrire dans la PR et amender l'ADR dans le même commit).

## À livrer

1. **Migration** `Version2026110…` (additive, rejouable) : `recipe.marmiton_id VARCHAR(32) NULL` + `CREATE UNIQUE INDEX … WHERE marmiton_id IS NOT NULL`, `recipe.source_url VARCHAR(255) NULL`, unité `pincee` (`INSERT … ON CONFLICT (slug) DO NOTHING`, mêmes colonnes que les autres unités sans dimension). Test de migration comme `RecipeFavoriteMigrationTest`. Compatible avec le code précédent (ADR 0017 règle 6).
2. **Domaine** : `Recipe::MARMITON_OWNER_ID`, `Recipe::createMarmitonNeutral(...)` (jamais secrète, originale, `marmiton_id`, `source_url`), `isMarmitonNeutral()`, `getSourceUrl()` ; `Recipe::copyFromOriginal` reprend `source_url` (pas `marmiton_id`) ; validation de `source_url` dans `Recipe` (forme de `MarmitonUrl::canonical()`). Entité Doctrine, repository (`findMarmitonNeutral(string $marmitonId)`, `findCopyOf(string $originalId, string $authorId)` — une requête chacune —, `saveNeutral`), `InMemoryRepository`, builder.
3. **Service d'application partagé** extrait de `CopyRecipeHandler` (le rapprochement des ingrédients et la copie) : `CopyRecipeHandler` et le nouvel import l'appellent, **sans dupliquer** une ligne. `CopyRecipeHandlerTest` et son budget ne changent pas.
4. **Cas d'usage** `ImportMarmitonRecipe` (`Application/Command/ImportMarmitonRecipe/`, command + handler ; le handler **rend** `ImportedMarmitonRecipe {recipeId, created: bool}` : ADR 0015 §12) : dans l'ordre de l'ADR 0037 décision 9 ; `MarmitonUrl::parse` d'abord, le plafond de 2 000 recettes avant tout appel sortant, le limiteur **seulement** quand la page doit être lue, **verrou consultatif** par identifiant avant de créer la neutre (`pg_advisory_xact_lock`), la neutre construite avec MAR-002 (`MarmitonIngredientLineParser` ligne à ligne, lignes ignorées si `null` ; **zéro ligne lisible = `recipeUnreadable`, rien n'est écrit**), la résolution des ingrédients de la décision 6 (a, b, c), le catalogue lu par le port `CatalogOwnerCommandPort` (aucun passe-droit `ROLE_ADMIN`) et ses ingrédients « de base », des lignes **toutes** dans une seule transaction (le bus est transactionnel) ; au plus 100 lignes (`Recipe::MAX_ROWS`). Aucun événement `RecipesOrIngredientsCreatedEvent` pour la neutre ; celui de la copie suit le chemin normal. Nom par `MarmitonRecipeTitle`, personnes par `MarmitonServings`, type par `MarmitonRecipeCategory` (type absent des données : le premier par ordre), le tout par `StringTool::capitalizeFirst` pour les noms (ADR 0030 : `NamesStartWithACapitalTest`).
5. **Controller** `Infrastructure/Http/Api/ImportMarmitonRecipe/ImportMarmitonRecipeApiController` : `POST /api/v1/recipes/import/marmiton`, `#[IsGranted('ROLE_USER')]`, corps `{url: string}` obligatoire (≤ 2 000 caractères, `422` sinon), `201`/`200` + `Location`, pas de corps, `#[OA\…]` complet avec les erreurs ; **la route est déclarée avant `/recipes/{id}/…` sans conflit** ; `MarmitonImportException` → 422 (trois), 502 (`unavailable`) au format `{error:{message}}` ; `429 MARMITON_IMPORT_RATE_LIMITED` + `Retry-After` par le limiteur `marmiton_import` (20/h/utilisateur, `lock_factory: BoundedLockFactory`, `EveryLimiterIsLockedTest`), consommé dans le handler par un port (pas dans le controller, car le contrôle dépend de l'existence de la neutre). Le tout est aussi soumis à `repas_write` comme les autres écritures.
6. **Droits** : `OwnerVoter` / `OwnershipLoader` — une recette dont l'auteur est `MARMITON_OWNER_ID` refuse `RECIPE_OWNER` à **tous**, administrateur compris (modifier, supprimer, favori, secret, planifier directement) ; `Recipe::changeSecret` / `changeFavorite` refusent déjà un non-auteur (vérifier qu'aucun chemin n'ouvre). Lecture : `GET /recipes/{id}` d'une neutre est permise à tout utilisateur (elle n'est pas secrète). Elle apparaît dans `GET /recipes/other-people` pour tous les comptes qui n'en ont pas la copie (aucune modification de `otherPeopleQuery` : un test le prouve), avec la recherche `q`.
7. **Lecture de la fiche** : `GET /api/v1/recipes/{id}` rend `sourceUrl` (clé toujours écrite, `string|null`), `RecipeDTO`, loader, mise à jour d'`openapi.json` (`make openapi`).
8. **Le propriétaire « personne » n'a aucune existence** : test sur la vraie base qu'aucun compte ne voit ses ingrédients (`IngredientVisibility`, fiche, recherche, doublons, fusion, amorçage, `ingredients/to-fix`), que `UserOwnedDataCoverageTest` n'a rien à purger, qu'aucune statistique n'est écrite, que `Ingredient::load` n'échoue pas.
9. **Budgets SQL** (`tests/Repas/WriteBudget`) : `importer-recette-marmiton` (neutre à créer), `importer-recette-marmiton-neutre-existante`, `importer-recette-marmiton-copie-existante`, chacun avec un nombre de requêtes **constant** quel que soit le nombre de lignes (résolution en masse comme `CopyRecipeHandler`).
10. **Docs** (même commit que le code) : ADR 0037 (amendements éventuels), `CLAUDE.md` (une puce « Copier une recette depuis Marmiton » et la liste des chantiers), skill `repas-dev` (case de la Definition of Done), `docs/api/openapi.json`, `docs/production.md` (retour arrière : l'ancien code ne protège pas la neutre), index de `docs/adr/README.md` (déjà posé), ce ticket passé à « fait ».

## Tests

- Handler (unitaire, `MarmitonInMemoryPageReader` + `InMemoryRepository`) : neutre inconnue (page lue une fois, neutre et copie créées), neutre connue (**le lecteur n'est pas appelé**), copie déjà là (rend l'existante, rien d'écrit), plafond atteint (aucun appel sortant), page illisible / introuvable / indisponible (rien d'écrit), ligne illisible ignorée, zéro ligne, deux imports du même lien l'un après l'autre.
- Résolution des ingrédients (vraie base, `DatabaseTestCase`, `tests/Repas/OutputAdapter/`) : (a) réutilisation d'un ingrédient de la neutre, (b) copie d'un ingrédient « de base » avec conversions propres et `adopted_from`, (c) création en `divers` ; la **copie d'un utilisateur amorcé retrouve ses propres ingrédients par provenance** (aucun doublon créé pour « Farine », « Beurre »…) ; un utilisateur sans l'ingrédient en reçoit une copie.
- Concurrence : deux processus (ou deux connexions) importent le même lien neuf : une seule neutre, aucun ingrédient orphelin (`CountersAreAtomicAcrossProcessesTest` donne l'exemple de vrais processus).
- API (`ImportMarmitonApiFlowTest`, vrais bus, lecteur simulé) : `201`, `200`, 401, 422 corps invalide, 422 les trois erreurs nommées, 502, 429 + `Retry-After`, `Location` lisible par `GET /recipes/{id}` avec `sourceUrl`, la copie est modifiable par son auteur, la neutre est `403` en écriture pour un administrateur, `404` jamais (elle existe), la neutre est dans « Recettes des autres » d'un autre compte et n'y est plus après la copie, `sourceUrl` reste sur une copie de la copie.
- Une fois, à la main, hors tests automatiques : un vrai import de la page d'exemple sur la base de développement (résultat dans la PR : lignes résolues, lignes « à régler »).
